# Executar a RQ05 (#46)

A análise usa exclusivamente o CSV final da #35. Não recalcula métricas,
não acessa o GitHub e não precisa de token. O dataset real de 300 repositórios
está em `output/metricas_repos.csv`; a interpretação do CFR (b) ainda depende
da validação na #34.

Com as dependências de `requirements.txt` instaladas, na raiz do repositório:

```bash
python -m analises.rq05 --entrada output/metricas_repos.csv \
  --coluna-frequencia frequencia_semana --saida output/analises/rq05 --escala-x log
```

Esse comando reproduz os resultados versionados. O mapeamento explícito de
`frequencia_semana` mantém compatibilidade com o contrato do dataset; os nomes
padrão da interface descritos abaixo continuam disponíveis para outros CSVs.
A escala log é válida porque todas as frequências da amostra são positivas.

## Entrada e unidades

CSV UTF-8, com ou sem BOM, delimitado por vírgula, uma linha por repositório.
Colunas extras são ignoradas. A interface assume estes nomes por padrão:

| Coluna | Tipo/unidade | Regra |
|---|---|---|
| `full_name` | texto | identificador preenchido e único, como `owner/repo` |
| `deployment_frequency` | real, releases/semana | frequência da definição principal; ≥ 0 |
| `cfr_ci` | real, fração 0–1 | CFR (a), proxy de CI |
| `cfr_entrega` | real, fração 0–1 | CFR (b), proxy de entrega |

Esses nomes são padrões da interface da RQ05, não uma alteração do contrato
da #35. Se o dataset usar outros nomes, indique-os explicitamente:

```bash
python -m analises.rq05 --entrada CAMINHO_DO_DATASET.csv \
  --coluna-repo full_name --coluna-frequencia frequencia \
  --coluna-cfr-ci cfr_a --coluna-cfr-entrega cfr_b \
  --saida output/rq05
```

Não há conversão automática de percentuais: CFR de 15% deve estar como `0.15`.
Campos vazios, `NaN`, `nan`, `NA`, `null` e `None` representam ausência.
Texto inválido, infinito, valores negativos, CFR > 1, colunas duplicadas
ou identificadores ausentes/repetidos interrompem a execução antes da gravação.

## Cálculo e casos sem estimativa

Para cada CFR, selecionam-se somente repositórios com frequência e esse CFR
preenchidos. A ausência de CFR (b) não exclui um repositório do teste de CFR (a).
Não há imputação nem alteração do CSV original. Os pontos são ordenados pelo
identificador, garantindo ordenação estável nos arquivos de saída.

O cálculo usa `scipy.stats.spearmanr` com hipótese bilateral, incluindo o
tratamento de empates por postos. Menos de três pares ou qualquer variável
constante produz `rho` e `p_valor` vazios, com situação explícita. O limiar de
três evita apresentar p-valores indefinidos para apenas dois pares.
Um CSV somente com cabeçalho produz duas linhas de resumo com n=0.

Os p-valores são aproximados, sem correção entre as duas variantes nesta RQ.
Como a [documentação do SciPy](https://docs.scipy.org/doc/scipy-1.14.1/reference/generated/scipy.stats.spearmanr.html)
ressalta maior precisão para amostras acima de 500 observações, o artigo deve
reconhecer essa limitação na amostra de 300. Não interpretar p alto como prova
de ausência de relação, nem p baixo como medida da força do efeito.

## Arquivos gerados e dicionário de dados

| Arquivo | Conteúdo |
|---|---|
| `correlacoes.csv` | duas linhas, uma por variante |
| `pares.csv` | pontos efetivamente usados nos testes e gráficos |
| `exclusoes.csv` | identificador e motivo de cada exclusão, por variante |
| `dispersao_cfr_ci.png` | frequência × CFR (a) |
| `dispersao_cfr_entrega.png` | frequência × CFR (b) |
| `relatorio.md` | tabela, leitura dos coeficientes, limitações e figuras |

Colunas de `correlacoes.csv`:

| Coluna | Tipo/unidade | Origem |
|---|---|---|
| `variante` | texto | `cfr_ci` ou `cfr_entrega` |
| `n_total` | inteiro, repositórios | linhas do CSV de entrada |
| `n` | inteiro, pares | frequência e CFR preenchidos |
| `n_excluidos` | inteiro, repositórios | `n_total - n` |
| `n_sem_frequencia` | inteiro, repositórios | frequência ausente |
| `n_sem_cfr` | inteiro, repositórios | CFR da variante ausente |
| `rho` | real, −1 a 1 ou vazio | coeficiente de Spearman |
| `p_valor` | real, 0–1 ou vazio | teste bilateral de Spearman |
| `situacao` | texto | `calculado`, `pares_insuficientes`, `variavel_constante` |

`n_sem_frequencia` e `n_sem_cfr` podem se sobrepor; não devem ser somados
para obter `n_excluidos`.

`pares.csv` contém `variante`, `full_name`, `deployment_frequency`
(releases/semana) e `cfr` (fração). `exclusoes.csv` contém `variante`,
`full_name` e `motivo`: `sem_frequencia`, `sem_cfr` ou ambos unidos por `;`.
Arquivos sem linhas preservam seus cabeçalhos.

O relatório registra o SHA-256 dos bytes de entrada, a versão do SciPy e o
mapeamento das colunas para rastrear os resultados. Reexecutar no mesmo
diretório substitui os seis arquivos; use diretórios diferentes para comparar
datasets ou configurações. A reprodução dos PNGs pressupõe o mesmo ambiente
de bibliotecas e fontes.

## Escalas e saída do comando

O padrão `--escala-x symlog` preserva frequência zero, mantém 0–1 release/semana
em escala linear e usa logaritmo acima disso. O CFR é exibido como percentual
no eixo vertical, embora o cálculo e os CSVs usem frações.

`--escala-x linear` usa escala linear. `--escala-x log` exige frequências
estritamente positivas entre os pontos usados; a execução recusa zeros e não
os descarta silenciosamente. Nenhuma escala modifica o cálculo da correlação.

Código 0 significa arquivos gerados, inclusive quando o resumo indica
correlação indefinida. Código 1 indica entrada inválida ou falha de leitura/
gravação. Código 2 indica argumentos inválidos. Consulte sempre `situacao`.
